# Security

Do not disclose credentials, exploit details affecting a live deployment, or private configuration in public issues or pull requests.

Use the affected repository's private vulnerability-reporting facility when enabled. If it is unavailable, ask the owner for a private reporting channel without including sensitive details in the public request. This policy does not imply that a reporting facility is already enabled or promise a response deadline.

Provide the affected revision, threat model, minimal reproduction and impact. Distinguish sandbox escape, policy bypass, credential exposure and denial of service. Test only systems you own or are authorized to assess.

Never attach production keys, personal fleet data, unredacted agent sessions, or artifacts containing secrets. Repository-specific security policies take precedence.
